# آيات — Ayat (Flutter / Android)

مشروع تأسيسي قابل للتشغيل والتطوير لتطبيق قرآن كريم عربي.

## الموجود في هذه النسخة
- واجهة رئيسية عربية RTL بتصميم أخضر زمردي وذهبي.
- شاشة مصحف تعرض آيات صفحة محددة من API، مع تقليب الصفحات 1–604 وحفظ آخر صفحة.
- شاشة قراءة متتابعة للسور والآيات.
- جلب قائمة القراء وبيانات المصاحف من MP3Quran API.
- تشغيل ملفات السور عبر just_audio.
- سبحة إلكترونية أولية.
- مركز إسلامي موسع بواجهات مستقلة للحديث والتخريج والتفسير والبحث في الكتب والمساعد الذكي.
- شاشة مواقيت صلاة متصلة بخدمة AlAdhan مع اختيار المدينة المصرية وطريقة الحساب.

## التشغيل
1. ثبّت Flutter SDK وAndroid Studio.
2. فك الضغط وافتح مجلد `ayat_flutter`.
3. نفّذ:
   ```bash
   flutter create . --platforms=android
   flutter pub get
   flutter run
   ```
4. لإنشاء APK:
   ```bash
   flutter build apk --release
   ```

## مصادر البيانات
- نص القرآن بالرسم العثماني: `api.alquran.cloud`
- القراء والتلاوات: `https://mp3quran.net/api/v3/reciters?language=ar`

## نقاط مهمة قبل النشر
- شاشة المصحف الحالية تجمع نص آيات الصفحة في تخطيط قراءة، وليست صورة طبق الأصل من صفحات مصحف المدينة. يلزم إضافة صور/ملفات صفحات مصرح باستخدامها أو مصدر صفحات موثوق، ثم اختبار المطابقة صفحةً صفحة.
- لا تعتبر الأذكار الحالية مكتبة نهائية موثقة؛ يجب مراجعة النصوص والأعداد ومصادرها قبل النشر.
- تنزيل الصوت أوفلاين، إشعارات الصلاة، القبلة، التفسير المتصل بالمصادر، الترجمات، البحث المتقدم، والمزامنة السحابية ما زالت تحتاج استكمالاً. شاشة مواقيت الصلاة الحالية تستخدم AlAdhan ويجب مراجعة الإعدادات مع توقيت المسجد المحلي.
- راجع شروط الاستخدام والترخيص ومعدل الطلبات لكل مصدر بيانات قبل النشر التجاري.
- يجب إجراء مراجعة شرعية/لغوية دقيقة للنصوص القرآنية والتشكيل قبل نشر التطبيق.


## الخطوط المضافة
- `KFGQPC_Uthmanic_Script_HAFS_Regular.otf`: الخط الأساسي لنص الآيات.
- `UthmanicHafs1_Ver13.otf.ttf`: خط حفص بديل مسجل في `pubspec.yaml` باسم `UthmanicHafs1`.
- خط الرموز التعبيرية المرفوع (حوالي 31 MB) لم يتم تضمينه في حزمة التطبيق؛ أندرويد يوفر دعم الرموز التعبيرية على مستوى النظام، وتضمينه يزيد حجم APK دون فائدة لازمة لعرض القرآن. يمكن إضافته لاحقاً كأصل اختياري إذا كان هناك استخدام محدد له.

بعد إضافة الخطوط شغّل:
```bash
flutter pub get
flutter clean
flutter run
```
تحقق بصرياً من جميع علامات الضبط والرسم العثماني على أجهزة Android مختلفة، وقارن النص بمصحف معتمد قبل النشر.


## التوسعة الإسلامية
- أضيف مركز أقسام للحديث الشريف، التفسير، المكتبة التراثية، الدراسة التفاعلية والمساعد الذكي. الواجهات موضوعة كبنية أولية؛ لم يتم الادعاء بأن موفري HadithDB أو Dalail أو Tarteel أو quran.ai متصلون داخل التطبيق بعد.
- أضيفت خدمة مواقيت صلاة فعلية عبر AlAdhan للمدن المصرية، مع إظهار طريقة الحساب.
- أسماء الخدمات المذكورة في التصميم تمثل مصادر تكامل مقترحة؛ يلزم الحصول على واجهات API/مفاتيح رسمية وشروط الاستخدام قبل الربط. لا تضع مفتاح OpenAI داخل تطبيق Android؛ استخدم خادماً وسيطاً يحفظ المفتاح بأمان.
- لا يصدر المساعد الذكي فتاوى؛ يجب عرض النصوص الأصلية والمراجع، وتمييز الملخص الآلي عن كلام العلماء، وإحالة النوازل إلى أهل الاختصاص.

## تحديث V3 – البحث القرآني

أضيفت شاشة بحث فعلية في نص القرآن الكريم:
- البحث بالكلمات والعبارات عبر خدمة AlQuran Cloud.
- عرض نص الآية واسم السورة ورقم الآية.
- نسخ نص الآية إلى الحافظة.
- حفظ الآيات محلياً على الجهاز وإدارتها من تبويب المحفوظات.
- فتح البحث من الصفحة الرئيسية أو من المركز الإسلامي.

### صلاحية الإنترنت في Android
تأكد من وجود السطر التالي داخل عنصر `<manifest>` في الملف `android/app/src/main/AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

### ملاحظات الإصدار
- يعتمد البحث على اتصال الإنترنت.
- الآيات المعروضة تأتي من AlQuran Cloud؛ راجع بيانات المصدر وشروط استخدامه قبل النشر التجاري.
- لم يتم بناء APK أو إجراء اختبار Flutter فعلي في بيئة التطوير الحالية، لذلك يلزم تشغيل `flutter pub get` ثم `flutter analyze` وتجربة التطبيق على جهاز Android قبل النشر.
- أقسام الحديث والتفسير والمساعد الذكي ما زالت تحتاج ربطاً مستقلاً بمصادرها وخادم وسيط آمن؛ لا تعتبر واجهاتها الحالية اتصالاً مباشراً بتلك الخدمات.

## إصلاح بناء Android في GitHub Actions (V12)

لم تكن حزمة المصدر الأصلية تحتوي على مجلد `android/`، لذلك يفشل الأمر `flutter build apk` عند البحث عن `android/app/build.gradle`. أُضيف سير عمل GitHub Actions في `.github/workflows/android-apk.yml` ينشئ ملفات Android أولاً باستخدام `flutter create . --platforms=android`، ثم يجلب الاعتماديات ويحلل المشروع ويبني APK ويرفعه كـ Artifact باسم `ayat-release-apk`.

إذا كنت تستخدم سير عمل Klencod الحالي بدلاً من الملف المضاف، أضف هذه الخطوة **قبل** `flutter pub get` و`flutter build apk`:

```yaml
- name: Generate Android platform files
  run: flutter create . --platforms=android --org com.ayat --project-name ayat
```

ثم أعد تشغيل البناء. هذه المعالجة تصلح الخطأ الظاهر في السجل؛ نجاح APK النهائي يظل مشروطاً بمرور `flutter analyze` وبقية خطوات Gradle.
